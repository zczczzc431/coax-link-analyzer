# 系统架构与算法

## 数据与控制分工

FPGA 负责高速样点接入、帧缓存、触发、冻结及部分链路统计；Linux 负责触控交互、时频分析、参考管理、异常事件生命周期和证据存储。冻结帧通过受控邮箱/缓存读出，控制和读回必须遵守匹配的地址、版本及身份合同。

本次发布的应用沿用原板硬件地址和 ABI；编译成功不使它自动兼容其他地址映射。`software/reference/dacctl.c` 是历史合同参考，默认 dry-run，不应替代当前正式控制工具。

## 参考学习与异常判定

正常链路学习阶段建立幅度与频谱参考。运行时组合 RMS/Vpp、频率与合格频点上的 MASK 变化，避免只用一个总幅度值描述链路状态。弱谱线、频段范围与噪声背景需要资格审查；资格不足时不能无条件进入监测。

RMS 的基本定义为 `sqrt(sum(x[n]^2)/N)`；去直流的 AC RMS 使用 `x[n]-mean(x)`。相对幅度变化按 `20 log10(A/Aref)` 表示。FFT 窗函数改变相干增益与噪声带宽，两者必须分别处理。

对于采样率 `Fs`、FFT 点数 `N` 和窗口 `w[n]`：

```text
bin_spacing = Fs / N
ENBW_bins   = N * sum(w[n]^2) / sum(w[n])^2
ENBW_Hz     = bin_spacing * ENBW_bins
```

增加显示小数位、插值估计峰值或缩小绘图区，都不会直接缩小 RBW。DDC 路线先混频、抗混叠滤波与抽取，再进行长记录频谱计算。

## 事件与证据

MONITOR 保存异常前、起点、最坏和恢复关键帧，并记录事件次数、持续时间、判据及质量状态。恢复要求配置的正常保持时间和连续正常条件同时满足；HOLD 不控制原始采样周期。

频谱证据由独立存储线程处理。排队、正在写、持久化完成和写失败是不同状态；索引提交不能早于数据持久化。已有回归覆盖写入、同步、索引发布故障以及退出时的保存合同。

## 反射与扫频

SWEEP 通过正常参考与被测状态比较相对响应；REFLECT 使用同一路接收通道分时采 Forward/Reverse，依赖接线、终端和校准条件一致。其结果适用于本原型的相对比较，不等同于同时矢量采集、完整双端口校准或故障距离定位。
